# Option A (containment): NATIVE-SIMULATOR evidence

*30 Oct 2026, from PR #58's branch at the commit this file lands in. Evidence tier **NATIVE-SIMULATOR** only: the real app, built Release for the iOS 27 simulator (iPhone 18 Pro, Xcode 27), against the shared local Supabase stack **with the Option A migration applied**, this branch's own `ai-gateway` and the model stub in **replay** mode with hand-written replies (deterministic, no model variability; see "What the replies were"). The rows are `option-a-device-checklist.md`'s. Nothing here is VERIFIED: that label is the founder's device pass. Readiness stays NOT READY.*

## How it was wired

- The app follows `EXPO_PUBLIC_SUPABASE_URL` for everything, so the build was pointed at a harness-only reverse proxy on :54398 that forwards `/functions/v1/*` to this branch's gateway (:8010, `deno run … ai-gateway/index.ts` with `ANTHROPIC_BASE_URL` at the stub on :8793) and everything else to the local stack (:54321). The proxy can hold a gateway reply (`/__delay`) for row 7. The proxy lives outside the repository.
- Replies: `e2e/replies/option-a-*.json`, written by hand in the model's output shape (committed; synthetic people, fictional facts). The stub answers each note by its exact words, so the notes were pasted or typed exactly as in `e2e/.captured/option-a-notes.txt`. Row 12's rest has two variants, selected per send with the stub's `/__variant`.
- Two local test accounts (`e2e/make-local-account.mjs`; the second with a short password set through the local admin API for the simulator keyboard). Screenshots in `docs/product/screens/option-a-sim/`.

## Two defects found and fixed on the branch during the pass

1. **"Tell the rest" from a person's page did nothing visible, and the next note from that page carried no link.** The Kept card, the look-over sheet and the Source view all live on the person's page; `tellRest` set the draft and a focus request, but only Today's dock listens for the request. Fix: the page opens its own Tell sheet on the request; the page's sheet carries the request's link into `keep`; the flow clears the request once the linked note is kept, so no later note (from any surface) is linked twice; the dock clears its own copy of the link when the request clears. Proof added to `optionA.test.tsx` ("a person's page tells the rest through its own sheet: the link is carried once, then answered"). Rows 3, 4, 12 and 13 ran on the fixed build.
2. **The look-over sheet's "Tell the rest" label rendered at a third of its size** (iOS fit-to-width misfiring on the sheet's re-layout, the same class as the B7/B8 pill finding). Fix: `Pill` gained `fixedLabel` (never shrinks the label; keeps its width), used by the sheet's pill. Screenshot of the defect kept (`row12-sheet-pill-shrunk-before-fix.png`); rows 13 and 14 ran on the fixed build, and the dock's and Source view's pills were unaffected throughout.

## What the replies were (and what that does and does not prove)

The stub's replies are the model's output shape written by hand: ten plain facts for the ten-thing note, nine for the compound note (jazz and chess both resting on the last sentence), two for the rest, one for the dog, and so on. They make every row deterministic and let row 12 stage the founder's counterexample exactly. They prove the **pipeline, gateway, database, sync, Understanding and every screen** on these inputs; they do not prove what the live model proposes for these notes (that is the LIVE-MODEL tier in the PR, 19 Oct, and the founder's device pass).

The first install kept the previous account's session in the keychain across `simctl uninstall`; sign out from People → settings.
- The stub, gateway and proxy were this session's own (PIDs), stopped afterwards; the shared `functions serve` and stub were not touched; the local database gained only the two simulator accounts' rows.
